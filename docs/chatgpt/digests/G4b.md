## Hardware facts
- Board: ESP32-WROOM-32 dev board, USB-C, CH340C USB-serial. esptool reports chip ESP32-D0WD-V3 rev v3.1, dual core 240 MHz, crystal 40 MHz, MAC 88:57:21:b1:8c:90. Flash 4 MB (sketch max 1310720 bytes with default partition). Serial port /dev/cu.usbserial-1460 (macOS; use cu not tty). 3.3 V logic everywhere.
- Display: 3.2" ILI9341, 240x320, 65k colour, SPI. Used landscape 320x240 with tft.setRotation(3) (rotation 3 = landscape flipped; physical orientation chosen to suit how screen sits). Panel REQUIRES inversion ON (TFT_INVERSION_ON or tft.invertDisplay(true)).
- Touch: FT6236 capacitive, I2C addr 0x38, on same combo module (pin labels CTP_RST etc). Raw range x 0..240, y 0..320; bottom-left at rotation 3 reads ~x=240,y=320. Needs CTP_RST tied to 3V3 (floating or GPIO25 caused flaky/locked bus). INT optional, unused (planned GPIO14).
- Pins:
  - TFT SPI (VSPI): SCK/SCLK GPIO18, MOSI GPIO23, MISO GPIO19, CS GPIO5, DC GPIO27, RST: tied to 3V3 so TFT_RST = -1 (GPIO33 originally planned, caused white/half-awake screen), BL/LED GPIO32 (digital HIGH; PWM ledc calls failed on core 3.x) or tie to 3V3.
  - Touch I2C: SDA GPIO21, SCL GPIO22 (Wire / TwoWire(0), 100 kHz at start, 400 kHz works standalone). Optional INT GPIO14, RST GPIO25 (not used; RST to 3V3).
  - Planned Pi UART: ESP32 TX GPIO17 -> Pi RX GPIO15 (pin 10), ESP32 RX GPIO16 <- Pi TX GPIO14 (pin 8), common GND, 3.3 V both sides so no level shifter; Pi `enable_uart=1`, /dev/serial0, 1,000,000 baud (fallback 460800). Mentioned MIDI DIN would need 5 V shifting (not built).
  - Avoid strapping pins 0, 2, 12, 15. Onboard LED GPIO2.
- Power: from USB during dev; panel on 3V3. Keep wires short (<20 cm).
- Arduino IDE settings (working): Board "ESP32 Dev Module", Port /dev/cu.usbserial-1460, Upload Speed 115200 at first (later 460800/921600 suggested; 921600 reported stable by 2025-10-23), Flash Mode DIO, Flash Freq 40 MHz, Partition Default 4MB with spiffs (Huge APP (No OTA/1MB SPIFFS) suggested only for oversized image assets), Core Debug None, PSRAM Disabled. Serial Monitor 115200. Tools > Erase Flash > All Flash Contents clears stale core dump. Board URL https://espressif.github.io/arduino-esp32/package_esp32_index.json.
- Versions: esp32 Arduino core 3.3.2 (Espressif), toolchain esp-x32/2507 xtensa-esp-elf gcc 14.2.0, esptool v5.1.0, TFT_eSPI 2.5.43, LVGL 8.3.11 (v9 was installed first and is incompatible with all code), Adafruit FT6206 library (works for FT6236; also Adafruit GFX). EEZ Studio ~1.9+ with LVGL 8.3.x project type. Montserrat fonts.
- TFT_eSPI User_Setup.h final (in ~/Documents/Arduino/libraries/TFT_eSPI/): ILI9341_DRIVER; TFT_WIDTH 240; TFT_HEIGHT 320; TFT_MOSI 23; TFT_MISO 19; TFT_SCLK 18; TFT_CS 5; TFT_DC 27; TFT_RST -1; TFT_INVERSION_ON; SPI_FREQUENCY 40000000 (27000000 suggested as safer; 40 MHz works; Read_User_Setup output showed 40.00 MHz). User_Setup_Select.h must include User_Setup.h. TFT_BL defined in User_Setup.h clashes with a sketch-level `static const int TFT_BL`; pick one.
- lv_conf.h (LVGL 8.3 style, in SKETCH folder next to .ino, with `#define LV_CONF_INCLUDE_SIMPLE` before `#include <lvgl.h>`): LV_COLOR_DEPTH 16; LV_COLOR_16_SWAP 0; LV_TICK_CUSTOM 1 with Arduino.h/millis() (though loop also calls lv_tick_inc); LV_USE_LOG 0; dark default theme; LV_FONT_MONTSERRAT_14 on (10/12/18/20 etc must be enabled if generated UI uses them); user's own lv_conf.h had LV_MEM_SIZE 48*1024 and LV_USE_USER_DATA 1. Alternative global location ~/Documents/Arduino/libraries/lv_conf.h WITHOUT LV_CONF_INCLUDE_SIMPLE. Only one lv_conf.h should be active.
- LVGL driver recipe (v8): lv_color_t buf1[320*40] (~25 KB), lv_disp_draw_buf_init, lv_disp_drv with hor_res 320, ver_res 240, flush_cb using tft.startWrite/setAddrWindow/pushImage((uint16_t*)color_p)/endWrite; tft.setSwapBytes(true); indev pointer read_cb with rotation-3 mapping x=map(p.y,0,320,320,0), y=map(p.x,0,240,0,240) clamped; loop: lv_tick_inc(now-last); lv_timer_handler(); delay(5).
- Touch mapping per rotation (raw p.x 0..240, p.y 0..320): rot0 x=p.x->0..SW,y=p.y->0..SH; rot1 x=p.y->0..SW,y=p.x->SH..0; rot2 x=p.x->SW..0,y=p.y->SH..0; rot3 x=p.y->SW..0,y=p.x->0..SH.
- Colour fixes tried (purple = wrong swap; double-swap of LV_COLOR_16_SWAP 1 + setSwapBytes(true) is wrong). Working combo: LV_COLOR_16_SWAP 0 + setSwapBytes(true) + pushImage + invert ON. Green screen in EEZ attempt came after assistant suggested LV_COLOR_16_SWAP 1 (wrong for this setup).

## Decisions
- ESP32-WROOM-32 + ILI9341/FT6236 chosen/kept (also stated: ESP32 handles real-time touch/GUI; Pi runs logic).
- Pi link: GPIO UART (Serial1, 1 Mbps) with NDJSON, USB serial for dev; keys short, e.g. {"t":[x,y,bank],"seq":n}, {"cc":[id,val,ch]}, {"hb":1}. Pi side python pyserial + ujson on /dev/serial0. Assistant says UART is standard practice. Later: USB-MIDI/BLE-MIDI optional. Park until GUI done.
- LVGL 8.3.11 (not 9) pinned for stability and Arduino examples; GUI via LVGL with TFT_eSPI flush.
- Colour theme (assistant-stated, "Holson / Midibox GUI"): bg #0E0E10, primary text/borders ice blue #A8FFF9, secondary cyan #00E0FF, tertiary magenta #FF5DCC, header text #F0F0F0, button active #1E2C4D, pressed #40FFFF, inactive #30363F. A second "Midibox Dark Neon Tech" palette was also generated: primary #00F0FF, accent amber #FF9900, surface #1C1F24, container #2A2E35, highlight #00C0E0, text #E0E0E0, secondary text #A0A0A0, borders #33373D, error #FF4C4C. Chat-working main-page code uses 0x0E1114 bg, 0x1A2530 cards, 0x86F4FF cyan text, 0x2A79D8 buttons. These palettes are inconsistent; treat as design intent, not verified.
- Fonts: Montserrat family; built-in LVGL sizes 10-28; ExtraBold titles 28, Bold 26 headers, SemiBold 18 labels, Medium 22 values, Regular 16 footer. In EEZ add multiple TTFs at once via Assets > Fonts > +.
- Corner radius ~8, flat with soft glow. Layout: landscape 320x240, header strip ("MIDI PLAYGROUND"), left chord card (Am / ACE), right 2x2 params (ATTACK, RELEASE, CUTOFF, RESONANCE), footer row (OCTAVE C, TRANSPOSE -/+, SCALE ARP). Pages planned: Main, Common?, Page 1-4 (user: "main common page 1 page 2 page 3 page 4"); 4 left bank buttons B1-B4 in earlier TFT_eSPI prototype; splash screen "MIDI PLAYGROUND by Holson Instruments".
- EEZ guidance: use containers for grouping/grid, keep container opacity 255 and bg_opa 0 (opacity 0 hides children).
- EEZ Studio dropped (2025-10-27 14:45) as too hard for Arduino (EEZ Flow = C++ templates/namespaces; styles.c; huge images). SquareLine Studio chosen next (UI-only export, flat in sketch root).
- EEZ project settings: initially 240x320 portrait, LVGL 8.x, colour 16 bit, target ESP32; canvas orientation changed by swapping W/H to 320x240 (no rotate toggle); match LV_HOR_RES 320 and tft.setRotation(1 or 3).
