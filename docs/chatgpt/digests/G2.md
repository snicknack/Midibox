### 27 - Fatar keyboard integration (2025-09-29 22:50 to 2025-10-04 10:01, 182 msgs)
Started as "how does a Fatar keybed connect to a main board". User has a dead Studiologic SL88 main board; the keybed's own interface board (STM32F103C8T6 + 74HCT238) talks to the dead main board over a 5-wire harness. User got a Kingst LA1010 logic analyser (KingstVIS), powered the interface board from a bench PSU, and probed the three data wires. Went through UART guesses (31250, 38400, 115200 all gave framing errors) and settled on SPI-like, continuous, no chip select. Mapped the stream as "row marker byte then column byte". Never completed a key-to-note map; ended with user stressed that the stream looked random and being told to use 5 to 10 MHz sampling plus glitch filter.
- Hardware facts:
  - 5-wire harness (JST/Molex style, not DIN): red = +5 V, green = GND, yellow/blue/white = 3 data lines (user-confirmed). In the LA the lines were coloured magenta (Ch0), blue (Ch1), green (Ch2).
  - Interface board ICs: STM32F103C8T6 (ARM Cortex-M3, marked "GH28B CHN GH 411") and 74HCT238 (U1, 3-to-8 decoder, row strobes). Long black headers J2/J4 take the keybed ribbons. A grey flat cable runs into a red header.
  - 74HCT238 pins per the assistant: Y0..Y7 = pins 15,14,13,12,11,10,9,7 (active low); VCC 16; GND 8.
  - Bench PSU QW-MS305D: set 5.00 V, current limit about 0.20 A; board draws roughly 30 to 100 mA. Main board is dead so cannot power from synth.
  - LA1010 set to 3.3 V CMOS, Vth 1.65 V; sample rate advised 5 to 10 MHz (100 MHz fills 1 MSa in 10 ms).
  - Logic levels: STM32 side is 3.3 V; assistant advised pull-ups to 3.3 V never 5 V.
  - Decoded stream (Mac decode, SPI Mode 0 CPOL=0 CPHA=0, MSB first, 8 bit, CS none): SCLK about 60 to 140 kHz (measured about 65 kHz in one shot, "up to 130 kHz"); MOSI (magenta, Ch0) carries data; MISO (blue, Ch1) is mostly 0xFF with occasional 0xBF; SCLK (green, Ch2). A 10k pull-down on blue did not stop it reading, so blue is probably driven; assistant said ignore MISO. User earlier saw blue drop just before bursts (looked like CS) but decoder with CS errored; later treated as MISO.
  - A burst/frame appears about every 15 ms (about 66 Hz); first bytes of a frame looked like header/counter (e.g. 0x1B, 0x29; also "05 CC" mentioned).
  - Marker/column format (assistant's interpretation, not confirmed on a key): walking-zero marker bytes FE FD FB F7 EF DF BF 7F = row 0..7, each followed by a column byte (FF = no key; a 0 bit = closed contact). A key press produced "0xFF to 0x7C" once (bits 7,1,0 low) which was read as dual contacts plus a flag. Dual-contact timing delta = velocity. Aftertouch probably not on the 3 data wires (analog).
  - Keyboard has velocity, aftertouch, 88 keys. Quoted from user's design overview: Fatar MIDI keyboard.
- Code produced:
  - `spi_to_midi.py` (message "Assistant 2025-10-04 08:32"): Pi script using spidev/mido that parses marker+column pairs, computes velocity from first/second contact time, has a KEYMAP {(row,bit): note} and AUTO_ASSIGN mode. It is flawed: the Pi SPI cannot sniff a bus whose master is the STM32 (assistant admitted this at 08:35). Never run.
  - `csv_markers.py` (message 2025-10-04 09:49): prints ROW marker then COL byte from a KingstVIS CSV export. DEC2HEX Excel and awk one-liners for hex view.
  - Mac setup: Sigrok app bundle crashed on missing /usr/local/opt/python@3.12 and /usr/local/opt/dbus (Intel Mac, MacBookPro14,3, macOS 13.7.1); fix suggested `brew install dbus python@3.12`, `brew install sigrok`, `brew install --cask pulseview`; user then used KingstVIS instead.
- Decisions: Don't try to sniff with the Pi; use the logic analyser to reverse-engineer. Assistant recommended (2025-10-04 07:05) that since the main board is dead, bypass the STM32 SPI and scan the Fatar matrix directly (74HCT238 row strobes, read columns with GPIO expanders such as SX1509/MCP23S17, velocity from dual contacts), or buy a Fatar to MIDI encoder (Doepfer etc.). Not yet chosen.
- Problems: UART decode framing errors (not UART). Mislabelling of CS vs MISO. Idle stream not constant 0xFF, user found it hard to tell a key press; frame boundary guidance (15 ms gap) given. Unsolved: no key-to-(row,bit) mapping, no confirmation of whether velocity is sent or timestamps must be derived.
- End state: user seeing "patterns but not perfect walking" at 5 MHz; next step was to capture one frame at idle and one with a held key and diff.

### 30 - Capacitive and analog inputs (2025-09-30 13:19 to 2025-10-01 23:09, 181 msgs)

Decided: MPR121 for all capacitive (transport pads and encoder touch), ADS1115 (not the CD74HC4067 mux) for pitch/mod wheels and two faders, SX1509 for encoders (A/B/switch) and LEDs. SX1509 and ADS1115 got working; encoders work in polling mode; ADS1115 calibration finished; design box V1 agreed.
- Hardware facts:
  - Bought boards seen in photo IMG_2285: PCF8574, Adafruit MPR121, CD74HC4067, SX1509.
  - I2C addresses: FT6236 touch 0x38; MPR121 0x5A (0x5A to 0x5D); ADS1115 0x48 (ADDR to GND; 0x49 to 0x4B alternatives); SX1509 0x3E (alt 0x3F). Confirmed in i2cdetect: 0x38 and 0x3E.
  - SX1509 wiring: 3V3 to Pi pin 1; GND to pin 6; SDA to GPIO2 (pin 3); SCL to GPIO3 (pin 5); INT to GPIO22 (BCM, pin 15); RST to GPIO27 (pin 13) or tied to 3V3 via 10k; OSC unused. Both SDA/SCL header sides are the same nets.
  - SX1509 board silkscreen is wrong: labelled P0/P1/P2 are actually P8/P9/P10. Encoder ENC1 wired A=P8, B=P9, SW=P10 (code pin numbers).

  - Breadboard fault: rows linked horizontally not vertically; loose RST lead also caused flaky SX1509.
  - ADS1115: 3 bought (2 spare), user soldered header. Pot ends 3.3 V and GND, wiper to A0..A3, never 5 V. Mapping: AIN0 pitch wheel, AIN1 mod wheel, AIN2 fader A, AIN3 fader B. Optional 100 ohm + 100 nF RC on each wiper. Mod wheel raw range was 32 to 92 (software calibration needed).
  - Faders chosen (at that time): 60 mm linear 10k, suggested Bourns PTA6043-2015CPB103 (alternatives PTA3043/4543/8043, ALPS RS6011/RS6012). Superseded in chat 29.
  - Transport: 6 pads (Jog L, Jog R, Stop, Play, Record, Loop) with MPR121 electrodes plus WS2812B/SK6812 mini 3535 RGB LEDs under silicone pads (5 V, level shifter 74AHCT125 or 74HCT245 suggested); HTTM pads rejected (LED hard-wired).
  - Design Box V1 (AI render approved): angled matte black, 6 transport pads bottom left, pitch+mod wheels (pivot) middle left, two faders, 3.2" FT6236 touchscreen, 5 encoders (4 bottom right + 1 top right). Keyboard to be on under-desk pull-out hinges; Midibox on desk. Step 4 "Hardware Design" added to Midibox PM.
